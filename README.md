# בדיקה מהירה - אפליקציה עצמאית לבדיקה קולית של אביזרי הרמה (גרסה 3.2)

PWA ל-Chrome באנדרואיד, ללא שרת. בשטח רק אומרים; ההשוואה לרשימה הקודמת נעשית בסוף.

```
קובץ ריכוז (xlsx) → בחירת אתר → בדיקה בשטח → סיכום (השוואה: ישן / חדש) → ייצוא
```

## בשטח

| אומרים | קורה |
|---|---|
| `מיקום מחסן` · `מיקום חדש ארובה` · `החלף מיקום דנה רוני` | המיקום נשאר פעיל עד שמחליפים אותו. מיקום שלא בקובץ מתווסף. |
| `סוג רצועה עגולה ירוקה 4 מ'` · `סוג חדש ...` · `החלף סוג ...` | הסוג מותאם **לתבנית קיימת בקובץ** ונשאר פעיל עד שמחליפים אותו. |
| `2345/3` · `2345 לוכסן 3` · `קי 500158` · `07-2/1045` | המספר נרשם מיד תחת המיקום והסוג הפעילים. בלי חיפוש, בלי שאלות. |
| `2345/3 פסול חתך` · `2345 תקין תווית דהויה` | פסול + ליקוי / תקין עם הערה (נכנסת לליקויים עם מספר הפריט). |
| `פסול סדק` (בלי מספר) | על הפריט האחרון. |
| `בטל` · `חזור` · `מצב` · `עצור` · `המשך` | ביטול אחרון / הקראה / מונים / השהיה. |

חובה לומר את המילה **"מיקום"** או **"סוג"** לפני השם - כך האפליקציה מבדילה בין שם סוג ("4 מטר") לבין מספר פריט.

### סוגים - רק תבניות קיימות
- התאמה ברורה לתבנית מהקובץ → הסוג נקבע מיד (צליל עולה).
- כמה תבניות אפשריות → רשימה על המסך; בוחרים בנגיעה או אומרים את המספר (`1`, `2`...). עד הבחירה מספרים לא נרשמים.
- אין תבנית מתאימה → **"להוסיף סוג חדש?"** - כותבים בדיוק איך הסוג יופיע בתסקיר (ועומס, לא חובה). בלי אישור לא נוסף סוג.
- השם שנאמר נשמר ככינוי (גיליון "סוגים" בקובץ המיוצא) - בפעם הבאה אותו שם מזוהה מיד, בלי שאלה.
- **עומס עבודה בטוח** נלקח מעמודת "עומס עבודה בטוח (טון)" בקובץ הריכוז: העומס שרשום לרוב הפריטים מאותה תבנית (60% ומעלה).
  תבנית שהעומסים בה מפוזרים, או שאין לה עומס בקובץ - בלי עומס, ומשלימים בלשונית "סוגים" במסך הסיכום.
- רצועות: כשאין עומס בקובץ, העומס מוצע לפי הצבע שנאמר (סגול 1, ירוק 2, צהוב 3, אפור 4, אדום 5, חום 6, כחול 8, כתום 10 טון) וניתן לעריכה.

## לוח כתיבה (עט)
מיקום וסוג נקבעים כרגיל (קול או בחירה); את המספרים אפשר לומר **או לכתוב בעט**. כפתור **"כתיבה"** פותח לוח על 3/4 מסך (או חצי מסך).

- כותבים מספרים מופרדים בפסיק: `2345/3, 2346/3 פסול, K500158`. שורה חדשה או `;` נחשבים גם הם כהפרדה.
- **"פסול"** אחרי המספר פוסל אותו (גם `X` אחרי רווח, וגם ליקוי: `2346/3 פסול חתך`). לכפתור "פסול" אותה תוצאה בלי לכתוב.
- מתחת לשדה מוצג מה זוהה: ירוק = תקין, אדום = פסול, כתום עם `?` = לא זוהה כמספר.
- **"רשום N"** מכניס את המספרים לרשימה. מה שלא זוהה נשאר בלוח לתיקון. "בטל" מחזיר את כל הרישום ללוח.
- **לוח חדש לכל מיקום / סוג**: החלפת מיקום או סוג (בקול או בבחירה) רושמת קודם את מה שנכתב תחת המיקום והסוג הקודמים, ופותחת לוח ריק.
  אם נשאר בלוח מספר שלא זוהה - ההחלפה נעצרת עד שמתקנים או מוחקים אותו, כדי ששום מספר לא ייעלם.
- המיקרופון ממשיך לעבוד כשהלוח פתוח ("מיקום ...", "סוג ...", וגם מספרים).
- מה שנכתב וטרם נרשם נשמר במכשיר (גם אחרי סגירת האפליקציה).

**המרת כתב היד לטקסט נעשית על ידי המכשיר**, לא על ידי האפליקציה - הלוח הוא שדה טקסט גדול:
- Samsung (Tab / Ultra): הגדרות ← תכונות מתקדמות ← S Pen ← **S Pen לטקסט** (S Pen to text). כותבים ישירות על השדה.
- מכשירים אחרים (Android 14 ומעלה): Gboard ← הגדרות ← **כתיבה** ← "כתיבה בשדות טקסט" (Stylus handwriting).
- אם כתיבה ישירה לא עובדת ב-Chrome במכשיר מסוים: מקלדת כתב יד (Gboard ← שפות ← עברית ← כתב יד, או מצב כתב יד במקלדת Samsung).
- כדי ש"פסול" יזוהה, שפת המקלדת צריכה להיות עברית. ספרות, `/`, `-` ופסיק מזוהים בכל שפה.

## מסך הסיכום (סוף יום / סוף סשן)
ההשוואה לקובץ לפי **מספר + סוג** (המיקום לא משתתף):
- מספר מנורמל: `07-2/1045` = `7/2/1045`, `2345/03` = `2345/3`, `k500158` = `K500158`.
- סוג לפי משפחה (רצועה / שאקל / מענב שרשרת / מחגר...) - כי הניסוח בקובץ משתנה מתסקיר לתסקיר.
- נמצא → **ישן**, והמיקום בקובץ מתעדכן למיקום האחרון. לא נמצא → **חדש**, שורה חדשה בקובץ.
- **לבדיקה** (לא נחסם, רק מסומן): אותו מספר קיים בסוג אחר; התאמה חלקית (נאמר `500158`, בקובץ `K500158`); נמצא באתר אחר; זיהוי קולי בביטחון נמוך. לכל אחד אפשר לקבוע ידנית ישן / חדש.
- לשונית "סוגים": התיאור והעומס שייכנסו לתסקיר, לעריכה.

## ייצוא
- **קובץ ריכוז מעודכן** - אותו קובץ: מיקום מעודכן, שורות לחדשים (מקור "בדיקה בשטח"), עמודות הבדיקה הנוכחית
  (תאריך, תוצאה, ליקויים, מיקום נוכחי/קודם, סוג כפי שנאמר, עומס, פריט חדש, לבדיקה, ביטחון), וגיליונות:
  `נבדקו <תאריך>`, `לא נבדקו`, `סוגים`, `מיקומים`. נכתב כערכים - שמור את קובץ המקור.
- **נבדקו היום** - שורה לכל פריט עם הנתונים לתסקיר וסימון ישן / חדש.
- **JSON לתסקירים**:
```json
{ "clientName": "...", "site": "קישון", "date": "17/11/2026", "counts": { "total": 62, "old": 40, "new": 22, "fail": 1 },
  "groups": [ { "location": "מחסן כלים", "type": "רצועת הרמה", "spokenType": "רצועה עגולה ירוקה 4 מ",
      "lines": [ { "description": "רצועת הרמה עגולה אורך 4מ'", "swl": 2, "quantity": 61, "serials": ["..."], "failedSerials": ["9120/7"], "newSerials": ["..."] } ],
      "defects": [ { "serial": "9120/7", "status": "fail", "text": "חתך / קרע", "isNew": true } ] } ],
  "moved": [ { "serial": "...", "from": "דנה רוני", "to": "מחסן כלים" } ], "notInspectedCount": 3120 }
```
כל `group` = תסקיר אחד (מיקום × סוג).

`lines[].swl` הוא עומס העבודה הבטוח **בטון** (`"swlUnit": "ton"`), או `null` כשלא נקבע עומס לסוג.
`missingSwl` מפרט את הסוגים שנשארו בלי עומס (`[]` כשהכול מלא) - כדאי לבדוק אותו לפני הפקת התסקירים.

בקובץ הריכוז המיוצא: פריט חדש מקבל את עומס הסוג בעמודת "עומס עבודה בטוח (טון)" (מקור העומס: "בדיקה בשטח");
פריט קיים שהתא שלו ריק - מושלם באותו אופן; עומס שכבר רשום בקובץ לא נדרס.

## הרצה
```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/
npm test         # מנתח קולי, לוח כתיבה, מנוע שטח, השוואה וייצוא
```
בטלפון נדרש HTTPS (GitHub Pages / Firebase Hosting).
